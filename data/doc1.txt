一、核心矛盾：3 万页与搜索引擎识别的拉锯战
关键词独立页面 = 3 万页面 = 极易触发 Doorway Page / Thin Content / Auto-generated Spam 三类惩罚。
Google 内部有一个不成文的标准：如果一个页面“和站内其他 1000 个页面只是换了 X”，那它就是低质的。你要做的不是“避开识别”，而是“做出 Google 不想惩罚的东西”。
所以本质是：用程序化效率做出来的东西，要让 Google 认为是“人工编辑过且有真实用户价值”的。
二、三条绝对不能踩的红线
判断标准：打开你自己生成的页面，关掉域名，问自己“如果这是个独立站，我会收藏它吗？”答“不会”就别上线。
三、3 万词的分层架构（最关键）
不是“一套模板打 3 万页”，而是分桶 + 差异化门槛：
┌─────────────────────────────────────────────────┐
│ Tier 1 头部词 200~500 个                          │
│   - Head terms（搜索量 > 1k，竞争激烈）           │
│   - 处理方式：人工深度编辑 / 资深作者撰写          │
│   - 字数 2000+，原创图表、案例、独家数据          │
│   - 目的：抢排名、撑权重、树权威                  │
├─────────────────────────────────────────────────┤
│ Tier 2 中长尾 3000~5000 个                        │
│   - Mid-tail（搜索量 100~1k）                      │
│   - 处理方式：模板 + 人工审核 + UGC                │
│   - 字数 800~1500，必须配 Schema + 内部链接       │
│   - 目的：覆盖搜索意图、积累长尾流量              │
├─────────────────────────────────────────────────┤
│ Tier 3 长尾 25000+ 个                             │
│   - Long-tail（搜索量 < 100，高度具体）           │
│   - 处理方式：程序化生成 + 质量门 + 抽样审核       │
│   - 字数 400~800，必须差异化 + 可被 AI 引用       │
│   - 目的：GEO 引用、语音搜索、零点击占位          │
└─────────────────────────────────────────────────┘
• 关键原则
  • 不要 3 万页都让 Google 索引。Tier 3 大量用 noindex + 仅在 sitemap 给搜索引擎做发现测试，质量起来再放。
  • 每层用不同的内容生成管线，别让算法看出“批量生产”的指纹。
四、让 3 万页不被判低质的技术架构
▍ 4.1 模板变体策略
  • 不是 1 个模板做 3 万页，而是 20~50 个基础模板 × 变体。
每页必须变化的元素（最少 5 项）：
    – Title、H1、Meta Description
    – 首段引导语（不能是同一句开头）
    – 中间小标题顺序、段落顺序
    – FAQ 内容（哪怕是相似问题，答案要写不同的）
    – 相关推荐、底部 CTA
▍ 4.2 内部链接网络
  • 孤儿页面 = 死页 = 必降权。
  • 每个新页面要至少 5~15 个相关内部链接。
  • 用 Topic Cluster 模型：每个 pillar page 辐射 50~200 个 cluster page。
  • 自动生成但要语义相关（不要硬塞链接）。
▍ 4.3 URL 架构
✅ /guides/seo/keyword-research-for-ecommerce/
✅ /industries/saas/competitor-analysis-tools/

❌ /keyword-research-1
❌ /city/seo/new-york
❌ ?keyword=xxx
▍ 4.4 Schema 必须全套
  • Article / BlogPosting + author + datePublished + dateModified
  • FAQPage（Tier 2/3 必加）
  • Organization + Person（作者实体，要可追溯到真人 LinkedIn/Github）
  • BreadcrumbList
  • 核心页加 HowTo / Product / Service
五、GEO 与 AI 引用获客（2025-2026 的真正战场）
AI Overview / ChatGPT / Perplexity 已经是新流量入口。AI 引用获客的逻辑和 SEO 完全不同，很多人还没重视这块。
▍ 5.1 AI 引擎“愿意引用”的内容特征
  • 段落可独立被引用：每段开头要有“定义性陈述”（“X 是 Y”），不依赖前文。
  • 包含具体数字 / 数据：AI 偏好有 Stat 的内容（“73% 的用户...”）。
  • 结构化清单 / 表格：AI 抽取成本低，引用概率 ×3。
  • FAQ 块直答：Question → 1~2 句直答 → 展开。
  • 明确的作者 / 来源：被 Knowledge Graph 关联的作者 / 品牌，引用率显著更高。
  • 被外部权威源引用：你引用 .edu / .gov / 行业报告，AI 也会信任你。
▍ 5.2 实战写法示例
错误（AI 不会引用）：
“选择关键词研究工具时需要考虑很多因素，
包括价格、功能、易用性等。”
正确（AI 高概率引用）：
“2025 年最值得关注的 5 个关键词研究工具是：
Ahrefs（每月 $99，适合中大型团队）、
Semrush（综合功能最强）、
Google Keyword Planner（免费）...”
▍ 5.3 GEO 的关键 Schema
{
  "@type": "Article",
  "author": { "@type": "Person", "name": "...",
              "url": "LinkedIn", "sameAs": [...] },
  "publisher": { "@type": "Organization",
                 "name": "...", "logo": {...} },
  "datePublished": "...",
  "dateModified": "...",
  "citation": [...],  // 引用源
  "about": [...],
  "keywords": [...]
}
六、AI 内容生成（不可避免时）的防检测写法
如果用 GPT / Claude 生成内容，直出必被识别。必须过“人化”流程：
  • 段落长度要变化：2 句话的段、5 句话的段、1 句话的段，混着来。
  • 加入第一人称经验：“我测试了 3 个工具后...” “我们在 XX 项目中发现...”
  • 加入主观判断和偏好：“我个人更推荐 X，因为...”（AI 生成的不敢写这个）
  • 加入未发表的数据 / 截图（AI 写不出来这个）
  • 段落顺序打乱（不按“是什么-为什么-怎么做”的固定套路）
  • 手工编辑 30%（每 10 段至少改 3 段，注入真实语言习惯）

九、核心心法总结
  • 3 万页不是为了“覆盖关键词”，是为了让 Google 觉得你是这个领域的权威站。
  • 权威站的标准不是“页面多”，是“每个页面都是这个主题下最值得读的”。
  • GEO / AI 引用是新流量入口，段落级优化比页面级优化重要。
  • Pruning 能力 > 生成能力，能砍的站比能堆的站活得久。
